# 감자 작전본부

매일 같은 길도, 함께 타면 이야기가 된다!

자동차에 사는 감자가 운행을 함께하고, 정체 구간에서 다른 차의 감자들과 익명으로 공동작전을 벌이고, 주차하면 그날의 작전일지를 쓴다. 팀 시나브로가 현대자동차그룹 차량용 앱 개발 공모전(Code your App into Pleos App Market)에 내는 작품이다.

저장소에는 두 가지가 있다. `web/`은 브라우저에서 도는 웹앱으로, 차량 신호를 시뮬레이터가 대신 보낸다. `android/`는 그 웹앱을 묶은 Android 앱으로, Pleos Connect에서 실행하면 Vehicle·NaviHelper SDK와 차량 속도에서 실제 신호를 받고, TextToSpeech·SpeechToText SDK로 말하고 듣는다. Android 앱은 Pleos Connect 에뮬레이터에서 내비 안내를 켜고 Virtual Console로 기어와 속도를 넣어, 출발부터 정체, 과속방지턱, 도착, 작전일지 저장까지 동작하는 것을 확인했다. 실제 차량에서는 실행해 보지 못했다. 다른 감자는 어느 쪽에서든 가상이다.

## 실행

Pleos Connect 에뮬레이터에서는 저장소의 release APK를 설치해 실행한다(아래 "APK").

```bash
adb install -r apk/시나브로_감자작전본부_release.apk
```

브라우저 시뮬레이터로 볼 때는 다음을 실행한다.

```bash
cd web
npm install
npm run dev
```

브라우저에서 `http://localhost:5173`을 연다. 오른쪽 위 "시뮬레이터"에서 차량 신호를 보내거나 "탑승부터 주차까지 자동 재생"을 누르면 탑승부터 도착까지 저절로 흐른다. 판교 출근길(실제 지도)은 약 5분, 다른 길은 약 2분 걸린다.

| 명령 (`web/`에서) | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm test` | 작전본부 코어 테스트 (Vitest) |
| `npm run typecheck` | 타입 검사 |
| `npm run build` | 프로덕션 빌드 (`web/dist`) |
| `npx astryx doctor --built .` | Astryx 디자인 시스템 준수 점검 |

## 테스트 환경과 화면 규격

- **대상 환경**: Pleos Connect Emulator v2.1.0, 2560×1440, 160dpi (Android API 34, Automotive). 공모전 2차 PT가 이 에뮬레이터 시연으로 진행된다.
- **화면 규격 대응**: 앱 창 폭에 비례해 기준 글자 크기를 키운다(1,700dp 창에서 약 27px). 버튼과 입력 높이는 2–3rem이라 같은 창에서 54–81px이다. 가로와 세로 창 모두 가로 스크롤 없이 나온다.
- **에뮬레이터에서 확인한 것** (2026-11-14, release APK): 설치와 실행, 앱 창 1682×1210에서의 화면 크기, Vehicle·NaviHelper·TextToSpeech SDK 연결, Virtual Console로 기어를 P → D → P로 바꿨을 때 출발(주행 잠금 화면)과 주차(작전 결과), 주행 중 화면 유지, 시험 값으로 넣은 정체와 공동작전, Pleos 내장 음성 재생(로그 기준, 화자 seoyoon).
- **에뮬레이터에서 확인한 것** (2026-11-15, TMAP 키를 넣은 release 빌드): 내비 안내(시흥동 → 삼평동, 약 2.9km) 중에 받은 회전 안내, 경로 위 정체 구간, 남은 거리. Virtual Console로 넣은 속도에 맞춰 왼쪽 계기판과 지도 위 감자 차가 함께 움직이는 것(`PERF_VEHICLE_SPEED`). TMAP 경로로 그린 3D 지도. 성남시 공공데이터의 과속방지턱 3곳 경고와 컵 계산. 어린이 보호구역 안내. 정체 구간에서 감자 부대 묶기. 도착 뒤 작전 결과, 답례 스티커, 작전일지 저장.
- **에뮬레이터에서 확인한 것** (2026-11-15 저녁, 커피 묻기를 넣은 release 빌드): 주차(P)에서 커피 운송작전을 켜면 감자가 Pleos 내장 음성으로 묻고, 그 말이 끝난 뒤 SpeechToText SDK(ON_DEVICE)가 에뮬레이터의 호스트 마이크로 들어온 한국어 대답을 알아듣는 것. 시연용 녹음("스타벅스 아이스 아메리카노 벤티, 뚜껑 닫았어")을 PC 스피커로 틀어 넣었고, 인식 결과 "스타벅스 아이스 아메리카노 벤티 뚜껑 닫았어"를 칩으로 확인한 뒤 그 컵(스타벅스 벤티 아이스, 뚜껑 닫음, 591ml)의 방지턱 상한 속도 시속 25km를 화면과 음성으로 알렸다. 한 번은 첫 낱말(브랜드)을 놓쳐 브랜드만 칩으로 고르게 했다.
- **브라우저에서 확인한 것**: Chrome 계열에서 창 크기 1680×1250, 1024×768, 375×812. Node 24.
- **확인하지 못한 것**: 내비의 과속방지턱 주의 지점(SPEED_BUMP) 이벤트(에뮬레이터 경로에서는 받지 못했다), 세로 창, 앱이 뒤로 가 있을 때의 동작, 실제 차량. 말로 묻기를 실제 차량 마이크와 서버 인식(HYBRID)으로 쓰는 것.
- **필요한 설정**: 없음. 기록은 기기 안(WebView의 localStorage)에만 저장된다. 주행 중 실제 지도를 그릴 때는 지금 위치와 목적지를 경로 서비스(TMAP, 키가 없으면 OpenStreetMap의 OSRM 공개 서버)에 보내고 지도 타일을 OpenFreeMap에서 받는다. TMAP 키(`web/.env.local`의 `VITE_TMAP_APP_KEY`)는 선택이다. Vite가 이 값을 웹앱 묶음과 APK에 그대로 넣으므로, 저장소의 `apk/`에는 키 없이 빌드한 APK를 둔다. 공공 API 키(`DATA_GO_KR_KEY`, `EX_API_KEY`)는 자료를 다시 받을 때만 쓰고 앱 묶음에 들어가지 않는다(아래 "실제 지도와 공공데이터").

## 음성

- 브라우저: 설치된 한국어 음성 가운데 가장 자연스러운 것을 고른다. Edge의 "Online (Natural)" 음성이 사람 목소리에 가장 가깝고, Chrome의 "Google 한국의"가 그다음이다. Windows 내장 음성(Heami)만 있는 브라우저에서는 기계음처럼 들린다. 설정 화면에서 지금 쓰는 음성을 확인하고 미리 들을 수 있다.
- Android 앱: Pleos TextToSpeech SDK로 말한다. 서버 음성을 쓰려면 Pleos Playground 자격 증명이 필요하다. `android/README.md` 참고.
- 말로 묻기: 커피 운송작전에 실은 커피를 감자가 묻고 듣는다(아래 "실은 커피 묻기"). Android 앱에서는 Pleos SpeechToText SDK로 듣고, 브라우저 시뮬레이터에서는 음성 인식을 쓰지 않고 글로 적는다(차량 마이크의 음성을 외부 음성 인식으로 보내지 않는다는 공모전 공지에 따라 음성 인식은 이 SDK 하나만 쓴다). 마이크는 Pleos 음성 서비스가 열고 소리를 글자로 바꾸며(기본 ON_DEVICE, 차량 안), 앱은 그 글자만 받아 컵을 고른 뒤 저장하거나 기록에 남기지 않는다. 주행 중에는 묻지도 듣지도 않는다.

## APK

- 위치: `apk/시나브로_감자작전본부_release.apk` (팀명 시나브로, 앱 이름 감자작전본부).
- 설치: Pleos Connect 에뮬레이터를 띄운 뒤 `adb install apk/시나브로_감자작전본부_release.apk`. 설치 뒤 앱 목록에서 "감자 작전본부"를 연다.
- 기어는 Virtual Console(`adb forward tcp:8088 tcp:8088` 뒤 `http://127.0.0.1:8088/`)의 Emulation Controls → Gear Selection에서 바꾼다. 자세한 순서는 `android/README.md`.
- 빌드 방법은 `android/README.md` 참고. release 빌드는 팀 서명 키가 정해지기 전까지 디버그 키로 서명한다.
- 저장소의 APK는 키 없이 빌드한다: `web`에서 `npm run build:public`(웹앱 묶음에서 `web/.env.local`의 `VITE_…KEY` 값을 비운다) 뒤 Gradle `assembleRelease`. 키가 없으면 경로는 OSRM으로 받는다. TMAP 키를 넣은 빌드는 시연 녹화에만 쓰고 저장소에 올리지 않는다.

## 시연 순서 (약 10분)

1. 감자 이름과 외형을 정하고, 운행 기록과 감자 교류에 각각 동의한다.
2. "도우미"에서 커피 운송작전을 켠다. 감자가 "오늘은 어떤 커피 실었어? 브랜드랑 사이즈를 말해 줘." 하고 묻는다. "스벅 벤티 아아, 뚜껑 닫았어"처럼 말하거나(마이크가 없으면 글로 적거나) 칩을 눌러 고르고 확인한다.
3. 시뮬레이터를 열고 "탑승부터 주차까지 자동 재생"을 누른다. 출발하면 화면이 잠기고, 실제 지도(판교 출근길, 약 5분) 위를 차가 달린다. 과속방지턱과 회전에서 컵 속 커피가 기울고, 감자가 음성으로 미리 알린다.
4. 길 위의 정체 구간에 들어서면 감자 부대가 묶이고 공동작전이 진행된다. 운전자가 누를 것은 없다.
5. 도착하면 작전 결과, 커피 운송 결과, 도착한 스티커, 그림일기(작전일지) 초안이 열린다. 답례 스티커를 보내고 일지를 저장한다.
6. 시뮬레이터의 운전 습관을 "거칠게"로 바꿔 다시 달리면 방지턱에서 커피가 넘치는 모습을 볼 수 있다.
7. 시뮬레이터에서 "일 년 뒤"를 누른다. 홈에 "1년 전 오늘" 회상이 뜬다.
8. "Pleos 연동"에서 각 신호가 실제 차량에서는 어느 SDK에서 오는지 본다.

에뮬레이터에서는 Virtual Console로 기어를 D에 놓고, 앱 오른쪽 위 "시험 값"의 "시험 주행 시작"을 누르면 내비가 준 실제 경로 위를 가상의 차가 달린다. 에뮬레이터의 차는 제자리에 서 있기 때문이다.

## 주행 지도와 커피 운송작전

주행 화면은 지도, 다음 회전, 도착 예정, 커피 컵(또는 경로 띠), 감자의 한마디로 이뤄진다.

**지도.** 통신이 되면 실제 3D 지도 위에 길을 그린다(아래 "실제 지도와 공공데이터"). 통신이 안 되면 내비(NaviHelper SDK)가 준 값만으로 약도를 그린다. 내비는 지도 그림을 주지 않고 "80m 앞 좌회전", "앞쪽 과속방지턱까지 120m", "400m 앞부터 정체" 같은 값만 준다. 약도는 그 값으로 길의 모양을 만든다(`web/src/core/drive.ts`). 굽이, 방지턱, 정체 구간, 도착지까지의 거리는 받은 값 그대로이고, 길가의 건물과 골목은 장식이다.

**커피 컵.** 컵 속 수면을 계산하는 모형이 있다(`web/src/core/cup.ts`). 운전자가 고른 컵(브랜드, 사이즈, 핫·아이스, 뚜껑)으로 계산하고, 고르지 않으면 기본 컵(뚜껑 없는 원통, 반지름 3.9cm, 높이 10cm, 420ml)으로 계산한다. 컵의 치수와 뚜껑의 효과는 모두 어림이다.

| 계산하는 것 | 방법 |
| --- | --- |
| 수면의 기울기 | 유효 중력에 수직. 옆으로 a만큼 가속하면 atan(a÷g). 오르막과 차체 기울기를 더한다. |
| 출렁임 | 원통 1차 슬로싱 모드 ω² = (g·ξ/R)·tanh(ξ·h/R), ξ = 1.841. 기본 컵에서 약 3.4Hz, 고른 컵은 입구가 넓을수록 느리다(약 2.9–3.5Hz). 감쇠비 0.1. |
| 회전에서 받는 힘 | 옆 가속 v²÷r. 내비는 반지름을 주지 않아 교차로 회전은 24m로 가정한다. |
| 과속방지턱 | 국내 표준 규격(길이 3.6m, 높이 10cm)의 턱을 속도 v로 넘을 때 차체의 위아래 가속도. 턱 위에서는 유효 중력이 줄어 수면이 더 크게 기울고, 0 아래로 내려가면 커피가 떠오른다. |
| 넘치는 양 | 수면이 가장자리를 넘은 깊이에 둑(위어) 유량 공식 Q = ⅔·Cd·b·√(2g)·e^1.5 를 적용한다. |
| 컵 모양 (어림) | 가게가 말하는 용량(톨 355ml)을 컵에 담긴 음료로 본다. 아이스는 얼음을 포함한 수면까지의 양이다. 그 용량대의 전형적인 컵(핫은 종이컵, 아이스는 플라스틱 콜드컵)을 같은 비율로 늘리거나 줄여 음료가 가장자리 1cm 아래까지 차게 하고, 그 컵을 가장자리 반지름이 같고 음료 양과 가장자리까지 남은 높이(1cm)가 같은 원통으로 바꿔 계산한다(`web/src/core/cupSpec.ts`). 수면이 가장자리 근처에 있어 기울기와 넘침은 가장자리 반지름이 정한다. |
| 뚜껑 (어림) | 닫은 뚜껑에서는 가장자리를 넘은 커피가 마시는 구멍으로만 샌다고 보고, 넘칠 양의 5%만 센다. 구멍 폭(약 1.2cm)이 둑 폭(컵 반지름, 약 4cm)에서 차지하는 몫 약 0.3에, 둘레 가운데 그 구멍이 수면이 솟는 쪽에 놓일 몫 약 0.2를 곱한 값이다. 실험값이 아니다. 회전의 안전 속도에는 뚜껑을 넣지 않는다(오래 기울어 있으면 구멍으로 계속 샌다). |
| 얼음 | 수면 높이에만 넣는다. 얼음이 출렁임을 줄이는 효과는 넣지 않았다(더 조심스러운 쪽). |
| 넘치지 않는 속도 | 고른 컵과 지금 든 양으로 방지턱과 다음 회전을 미리 계산해 알려준다. 기본 컵은 방지턱 시속 28km, 스타벅스 톨 핫(뚜껑 없음)은 23km, 벤티 아이스(뚜껑 닫음)는 25km, 메가커피 메가리카노 아이스(뚜껑 없음)는 15km(모두 어림). |

컵이 받는 힘은 두 곳에서 온다. 차량(헤드유닛)에 가속도 센서가 있으면 그 값을 쓰고, 없으면 길의 모양과 속도로 계산한다. 화면에 어느 쪽인지 적는다.

모형은 `web/src/core/drive.test.ts`(26개)와 `web/src/core/cupSpec.test.ts`로 확인한다. 예: 옆 가속 2m/s²에서 기울기가 atan(2÷9.81)에 수렴, 방지턱을 지난 뒤 수직 속도가 0, 시속 15km로 넘으면 넘치지 않고 50km면 넘침, 부드럽게 몰면 0ml·거칠게 몰면 57ml(기본 컵). 고른 컵에서는 더 가득 차거나 입구가 넓을수록 넘치지 않는 속도가 낮고, 가장자리까지 여유가 많을수록 높으며, 뚜껑을 닫으면 넘치는 양이 열린 컵의 약 5%다.

**실은 커피 묻기.** 주차한 채(기어 P, 탑승 전이나 출발 전)로 홈의 "커피 운송작전 켜기"나 도우미의 스위치로 커피 운송작전을 켜면, 감자가 보통 말로 "오늘은 어떤 커피 실었어? 브랜드랑 사이즈를 말해 줘." 하고 묻고 그 말이 끝나면 한 번 듣는다(`web/src/app/cupQuestion.ts`). Android 앱에서는 Pleos SpeechToText SDK로(`window.PleosHost.listen()`, 들은 말은 `{type: "stt"}` 메시지), 브라우저 시뮬레이터에서는 음성 인식 없이 글로 적고, Android 앱에서도 SpeechToText를 쓸 수 없으면 글로 적는다. 들은 말에서 브랜드(스벅·스타벅스 등 별칭), 사이즈(숏·톨·그란데·벤티·레귤러·라지·엑스트라·스몰·큰 거·작은 거, "24온스" 같은 용량), 핫·아이스(아아 = 아이스 아메리카노, 따뜻한·뜨거운), 뚜껑(닫았어·없어·빨대)을 알아듣고(`web/src/core/cupSpec.ts`), 낱말 칩으로 보여 준 뒤 확인을 눌러야 그 컵을 쓴다. "아이스 말고 따뜻한 거", "톨, 아니 그란데"처럼 고쳐 말하면 나중 말을 따른다. 못 알아들은 것은 칩으로 고르고(뚜껑을 고르지 않으면 뚜껑 없는 컵으로, 더 조심스럽게 계산한다), 아무것도 고르지 않으면 기본 컵이다. 확인하기 전에 그 컵의 "방지턱 시속 N km 아래면 안 넘쳐요 · 어림"을 보여 준다. 공식 수치가 없어 어림한 용량은 사이즈 칩에 "(어림)"이라고 적는다. 듣는 동안에는 감자가 다른 보통 말을 미뤘다가 다 들은 뒤에 한다(감자 목소리가 마이크에 들어가지 않게). 주행 중에는 묻지도 듣지도 않는다. 질문이 끝나기 전에 출발하거나 묻기를 그만두면 그 질문도 거두고(Android 앱은 출발 신호를 웹에 보내기 전에 버린다), 듣는 중에 출발하면 바로 멈추고 들은 것을 버린다. Android 앱에서는 Vehicle SDK가 기어 P를 읽었을 때만 묻고 듣는다. 기어 P가 확인되지 않으면 말로 묻지 않고 글로 적는 칸도 열지 않으며 칩으로만 고른다. 앱 화면이 가려지면(내비 전체 화면, 다른 앱) 듣기를 멈추고, 돌아오면 다시 말하기를 권한다. 고른 컵은 작전 결과와 작전일지("스타벅스 벤티 아이스(뚜껑 닫음) 591ml 가운데 12ml쯤 흘렸지만 98%는 지켜냈다.")와 그림일기의 컵(아이스는 얼음과 빨대)에 남는다.

컵 용량은 각 브랜드 공식 홈페이지의 메뉴·영양정보에서 2026-11-15에 확인했고, 공개 자료가 없는 몇 곳은 언론 보도나 흔한 컵 크기로 어림했다. 컵 모양은 종이컵(Dart Solo)과 콜드컵(Pactiv Evergreen Greenware) 규격표의 치수다. 출처는 `web/src/data/cups.json`의 `source`와 앱의 "Pleos 연동" 화면에 적는다.

한계: 컵의 치수, 뚜껑으로 새는 양, 얼음의 효과는 어림이고, 매장마다 실제 컵이 조금씩 다르다. 도로 경사는 내비가 주지 않아 실제 차량에서는 가속도 센서가 있을 때만 반영된다. 감속을 강제하지 않고 알려줄 뿐이다.

내비(NaviHelper)가 알려준 지금 위치와 목적지 좌표로 경로 탐색 서비스에서 길의 실제 모양을 받아, 기울인 3D 지도 위에 그린다.

| 무엇 | 어디서 |

| 길의 모양 | TMAP 자동차 경로안내 (`web/.env.local`에 `VITE_TMAP_APP_KEY`가 있을 때), 없으면 OSRM 공개 서버. 2026-11-15 확인: 시연 경로(시흥동 → 삼평동)에서 TMAP이 2,967m 경로를 주고, WebView에서 바로 부를 수 있게 CORS를 연다. |

| 휴게소와 커피 매장 | 한국도로공사 「휴게소 기준정보」, 「휴게소 브랜드 매장」 (고속도로 공공데이터 포털 API, 빌드할 때 받음) |
| 정체 구간 | 내비 값 그대로 (시뮬레이터에서는 가상) |

**지도 위의 차는 계기판과 같은 차량 속도로 움직인다.** Android Automotive의 차량 속성 `PERF_VEHICLE_SPEED`(CarPropertyManager, 권한 `android.car.permission.CAR_SPEED`)를 받아, 내비가 알려준 길 위를 그 속도로 나아간다. 내비의 위치가 바뀌면 그 위치로 맞춘다. Pleos Connect 에뮬레이터에서는 Virtual Console이 넣는 속도가 이 값으로 들어오므로, 왼쪽 계기판의 속도와 오른쪽 지도 위 감자 차가 같은 신호로 함께 움직인다. Pleos Vehicle SDK에는 속도 값이 없어 이 부분은 Android의 차량 속성 API를 쓴다. 차량 속도로 위치를 어림하는 동안에는, 내비가 막힌다고 한 구간에서 차가 실제로 시속 15km보다 느리게 갈 때만 정체로 본다.

경로에서 12m 안에 있는 방지턱만 그 길의 방지턱으로 본다. 시뮬레이터의 "판교 출근길 · 실제 지도" 시나리오는 시흥동(판교 제2테크노밸리)에서 삼평동까지 2.97km 실제 경로이고, 성남시 자료의 과속방지턱 3곳과 어린이 보호구역 2곳(성남송현초등학교, 삼평어린이집)을 지난다. 공공데이터 원본은 저장소에 넣지 않고 `scripts/build-opendata.py`로 성남시 일대만 추려 `web/src/data/opendata.json`에 넣는다.

좌표는 지도를 그리고 경로를 받는 데만 쓰고 저장하지 않는다. 작전일지에는 동네 이름만 남는다. 지도를 불러오지 못하면(통신 없음) 내비 값으로 그린 약도로 돌아간다.

**공공 API 자료는 빌드할 때 받아 앱에 넣는다.** 앱은 API 키를 갖지 않고, 실행 중에 이 API들을 부르지 않으며, 지금 위치를 보내지도 않는다. 받은 값은 `web/src/data/publicapi.json`에 있고, 비어 있으면 그 자료를 쓰는 기능만 쉰다(`web/src/core/publicdata.ts`가 형식을 확인한다).

| 기능 | 하는 일 | 자료가 없으면 |
| --- | --- | --- |
| 사고 다발 지점 | 경로가 지점의 범위(자료의 반지름, 한가운데가 경로에서 많아야 150m)를 지나면 실제 지도에 옅게 칠하고, 범위에 들어서기 150m 앞부터 칩("보행 어린이 사고 다발 지점 · 120m", 거리는 범위까지)을 띄운다. 범위에 들어서기 100m(빠르면 5초) 앞에서 감자가 "사령관님! 어린이 교통사고가 잦은 곳입니다. 살펴 가겠습니다." 하고 다른 말보다 먼저 알린다. 커피 운송작전에서 방지턱 경고가 곧 나와야 하면 방지턱 경고를 먼저 하고 이 경고는 그 뒤에 한다. 결빙 지점은 예보 기온이 3°C 이하이거나 12–2월일 때만 알린다. 미리 알리고 한가운데를 지나간 수만 작전 결과와 작전일지에 적는다(내비의 위치가 건너뛰어 알리지 못한 지점은 세지 않는다). | 표시하지 않는다 |
| 날씨 | 출발 시각에 가장 가까운 예보 한 시간(90분 안)을 쓴다. 발표한 지 24시간이 지난 예보와, 차가 예보 지역(판교 일대)에서 10km 넘게 떨어진 운행에는 쓰지 않는다. 예보에 비나 눈이 있으면 출발 인사가 "출발! 비 소식이 있으니 천천히 가자."로 바뀌고, 작전일지 첫 줄이 "맑은 저녁, 오후 6시 2분에 길을 나섰다.", "비 소식이 있던 저녁, …"처럼 날씨로 시작한다. 빌드 때 받은 예보이므로 비가 "온다"고 단정하지 않는다. Pleos 연동 화면에 들어 있는 예보로 날씨를 쓰는 기간과, 그 기간이 지났는지를 적는다. | 예전 문장 그대로 |
| 해 지는 시각 | 주차한 날의 값으로 그림일기의 하늘(낮, 해 지는 시각 앞뒤 30분의 해 질 녘, 밤)을 고르고, 해가 진 뒤에 도착하면 "해가 진 지 40분 뒤였다."를 덧붙인다. 성남에서 50km 넘게 떨어진 곳에 주차하면 쓰지 않는다. Pleos 연동 화면에 자료의 기간을 적는다. | 주차 시각으로 하늘을 어림한다 |
| 휴게소 커피 | 도우미의 커피 운송작전에 커피 매장이 있는 가까운 휴게소 세 곳을 보인다(지금 위치, 모르면 시연 출발지에서 잰 직선거리). 경로가 커피 매장이 있는 휴게소 500m 안(진행 방향 오른쪽)을 지나면 3km 앞에서 감자가 한 번 알린다. | 목록을 감춘다 |

판교 출근길 시나리오는 날씨와 해 지는 시각을 쓴다(날씨는 시나리오 시각이 예보 발표 뒤 24시간 안일 때). 2026-11-15에 받은 자료에서 시연 경로와 가장 가까운 사고 다발 지점은 1.1km 떨어져 있어, 이 시나리오에서는 사고 다발 지점 경고가 나오지 않는다. 지어낸 지점은 넣지 않았다. 휴게소 알림도 고속도로를 지나는 실제 경로에서만 나온다.

자료를 다시 받으려면 저장소 루트에서 `python -I scripts/fetch-public-apis.py`를 실행한다. 키는 `web/.env.local`의 `DATA_GO_KR_KEY`(공공데이터포털 일반 인증키, Decoding)와 `EX_API_KEY`(고속도로 공공데이터 포털 인증키)에서 읽는다. 두 이름에는 `VITE_`를 붙이지 않는다. 붙이면 Vite가 키를 웹앱 묶음과 APK에 넣는다. 스크립트는 받은 공개 자료만 파일에 쓰고 키는 쓰지 않는다. 한 출처가 실패하면 기존 파일의 그 항목을 이어 쓰고 그 항목을 받은 시각(`fetched`)도 예전 것을 둔다(`[이어 씀]`으로 찍는다). 사고 다발 지점, 예보, 출몰시각, 휴게소 네 출처가 모두 실패하면 파일을 그대로 둔다. 다시 받은 뒤에는 `web`에서 `npm run build:public`을 하고 APK를 다시 빌드한다(`npm run build`는 `VITE_TMAP_APP_KEY`를 묶음에 넣으므로 시연 녹화용 빌드에만 쓴다). 예보는 발표 뒤 24시간까지만 쓰므로, 시연 영상을 찍거나 발표용 APK를 만들기 직전에 다시 받는다. 시뮬레이터는 시나리오를 시작할 때마다 시계를 다음 출발 시각으로 돌리므로, 영상을 찍기 전에 시뮬레이터의 "실제 시각으로"를 누른다.

| 차량특화성 | 모바일 대비 차량만의 가치, 주행·정차 맥락과의 결합 | 모든 사건이 차량 신호(탑승, 출발, 정체, 주차)에서 시작한다. 주행 중에는 화면을 잠그고 실제 3D 지도와 음성으로만 안내하며, 결과는 주차 뒤에 공개한다. 커피 운송작전은 차의 가속과 과속방지턱으로 컵 속 커피를 계산한다. | 주행 화면, 작전 결과 |
| 창의성 | 독창성, Pain Point와 해결 방식 | 피할 수 없는 정체 시간을 익명의 공동작전으로 바꾼다. 좌표 없이 구간 이름으로만 묶고 정해진 스티커만 오간다. | 공동작전, 스티커 |
| 기술 활용성 | Pleos SDK·API가 핵심 경험에 쓰이는가 | 기능을 Vehicle, NaviHelper, TextToSpeech, SpeechToText SDK에 대응시켰고(FusedLocation 두 기능과 CarUxRestrictions는 2차 PT까지 붙일 계획으로, 앱 화면에도 그렇게 적었다), 신호마다 대응 API를 로그로 보여준다. 주행 지도는 NaviHelper의 위치·목적지·회전 안내·경로 위 정체로 실제 경로를 받아 3D 지도에 그리고, 지도 위 차는 Android 차량 속성(`PERF_VEHICLE_SPEED`)으로 계기판과 같은 속도로 움직인다. 경로 위 과속방지턱과 어린이 보호구역은 공공데이터에서 찾고, 사고 다발 지점, 날씨, 해 지는 시각, 휴게소 커피는 빌드할 때 공공 API에서 받아 넣는다. 주차한 채로 커피 운송작전을 켜면 SpeechToText SDK로 실은 커피를 말로 묻고, 그 컵으로 넘침을 계산한다. | Pleos 연동, 주행 화면, 도우미 |
| 사업성 | 타깃, 지속 이용, 확대 가능성 | 연속 탑승, 누적 기록, 그림일기, 추억 회상이 다시 탈 이유를 만든다. 임무(커피 운송작전, 주차비 돌려줘)는 카페·주차장 제휴로 넓힐 자리다. | 홈, 도우미 |

시연 영상은 Pleos Connect 에뮬레이터에서 이 앱을 직접 구동한 화면 녹화로 만들었고, 링크는 접수 메일에 적는다. GitHub 저장소 가산점은 소스 코드와 APK를 함께 요구한다. 릴리스 APK는 `apk/시나브로_감자작전본부_release.apk`에 있다.

## 디자인

- 디자인 시스템: Meta의 Astryx (`@astryxdesign/core`). 테마는 `web/themes/hq`.
- 색: 밝은 테마 강조색 현대 블루 `#002C5F`, 어두운 테마 강조색 액티브 블루 `#00AAD2`, 중립색 샌드 `#E4DCD3` 계열.
- 서체: Asta Sans (Pleos Connect 디자인 가이드의 공식 서체). 앱에 같이 묶여 있다.
- Pleos 디자인 원칙 Easy & Safe, Consistency, Glanceability를 따른다. 주행 화면에서 움직이는 것은 차의 실제 상태를 따르는 계기(지도, 컵)뿐이고, 꾸밈으로 움직이는 것은 없다. 주행 화면 안에는 누를 수 있는 것이 없고, 화면 위 띠에 시연용 단추("시험 값", 브라우저에서는 "시뮬레이터") 하나만 남는다.
- 감자는 동글동글한 몸에 볼터치와 짧은 팔다리를 붙인 고유한 캐릭터다(직접 그린 SVG). 평소에는 반말로 말하고 작전 중에는 "사령관님!" 하고 보고한다. 기획서의 "웃기고 하찮은 감자"다.
- 작전일지는 그림일기다. 그날 주차한 시각의 하늘 아래 감자가 차를 타고 달리는 그림이 붙는다.

## 구조

```
web/src/core/hq.ts        작전본부 코어. 상태 하나와 step(상태, 사건) 함수 하나. 순수 모듈.
web/src/core/hq.test.ts   코어 테스트. 사건 열을 넣고 결과 상태를 본다.
web/src/core/drive.ts     길과 차의 움직임. 내비 값으로 길의 모양을 만들고 컵이 받는 힘을 계산한다. 순수 모듈.
web/src/core/cup.ts       컵 속 커피의 움직임. 기울기, 출렁임, 넘침, 뚜껑. 순수 모듈.
web/src/core/cupSpec.ts   컵 목록(cups.json) 읽기, 말에서 브랜드·사이즈·핫/아이스·뚜껑 알아듣기, 컵을 원통으로 어림하기. 순수 모듈.
web/src/app/cupQuestion.ts 커피 묻기. 주차한 채로만 묻고 듣는다(SpeechToText SDK, 없으면 글).
web/src/core/publicdata.ts 공공 API 자료 읽기, 출발 시각의 날씨, 해 지는 시각, 가까운 휴게소. 순수 모듈.
web/src/core/drive.test.ts 위 두 모형의 테스트.
web/src/app/drive.ts      주행 엔진. 시뮬레이터, 실제 내비, 시험 주행이 같은 모양의 값을 화면에 대어 준다.
web/src/sim/              차량 신호원, 교류 중계, 음성 안내의 시뮬레이션 구현과 시뮬레이션 시계.
web/src/screens/          화면.
web/src/ui/               감자 그림과 공용 부품.
```

```
web/src/native/host.ts    Android 앱이 보내는 신호를 받는 입구.
web/src/native/hostSpeech.ts 말로 묻기 메시지({type: "stt"}) 읽기. android/…/ListenFlow.kt, WebBridge.kt와 짝.
web/src/app/signals.ts    시뮬레이터와 실제 차량이 함께 쓰는, 신호가 코어로 들어가는 한 길.
android/                  웹앱을 띄우고 Pleos SDK 이벤트를 신호로 바꾸는 Android 앱. android/README.md 참고.
```

코어는 신호가 어디서 오는지 모른다. 브라우저에서는 시뮬레이터가, Android 앱에서는 Pleos SDK가 같은 다섯 가지 신호를 넣는다. 교류 중계(다른 감자)는 아직 가상이며, 서버가 생기면 `web/src/sim/relay.ts` 자리에 갈아 끼운다.
